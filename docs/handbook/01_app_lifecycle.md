# 1. Mach-O Startup & Darwin Concurrency Initialization

When iOS launches TeeKum, the Darwin kernel executes `dyld` (the dynamic link editor) to map the application binary into memory, bind system libraries (`Network.framework`, `CryptoKit`, `CoreLocation`, `ActivityKit`), and transfer execution to the `$main` entry point generated by the `@main` attribute on `TeeKumApp`.

```
[OS Kernel / dyld] ──► Loads Mach-O Binary & Binds Frameworks
                           │
                           ▼
[Swift Concurrency Runtime] ──► Initializes Cooperative Thread Pool
                           │
                           ▼
[@main struct TeeKumApp] ──► Allocates SwiftUI State Boxes & Dependency Graph
                           │
                           ▼
[WindowGroup / AppRootView] ──► Evaluates Root Scene Hierarchy
```

### The State Allocation Dilemma in SwiftUI
In SwiftUI, `struct TeeKumApp: App` is an immutable value type that can be re-instantiated or copied by the SwiftUI layout engine. If service instances were declared as standard stored properties (`var service = LocationService()`), they would be recreated repeatedly. Wrapping services in `@State` instructs SwiftUI to allocate a persistent heap storage box (`Box<T>`) tied to the lifecycle of the application's root `WindowGroup`.

## 2.1 Concurrency Bridge: `SessionHolder`

```swift
/// Thread-safe Sendable wrapper to provide synchronous access to the active GroupSession
/// across actors and non-isolated closures without violating actor isolation boundaries.
public final class SessionHolder: @unchecked Sendable {
    private let lock = NSLock()
    private var _session: GroupSession?
    
    public init(session: GroupSession? = nil) {
        self._session = session
    }
    
    public var session: GroupSession? {
        get {
            lock.lock()
            defer { lock.unlock() }
            return _session
        }
        set {
            lock.lock()
            defer { lock.unlock() }
            _session = newValue
        }
    }
}
```

### Technical Rationale & Rosetta Stone
* **The Problem**: In modern Swift 6 concurrency, mutable state cannot cross concurrency boundaries without isolation (either via an `actor` or `@MainActor`). However, low-level high-frequency delegates (such as CoreAudio render loops or Network.framework socket read completions) execute on non-isolated background threads where `await actor.session` would introduce thread hops, task allocation latency, and potential deadlocks.
* **The Solution**: `SessionHolder` wraps the immutable `GroupSession` struct in a reference type marked `@unchecked Sendable`. Mutex locking via Darwin's POSIX-backed `NSLock` guarantees mutual exclusion.
* **Why `defer { lock.unlock() }`?**: Guarantees that even if an unexpected exception, stack unwind, or runtime trap occurs, the mutex is unconditionally released, preventing deadlock of the entire app.
* **Devirtualization**: The `final` keyword signals to the Swift compiler that `SessionHolder` cannot be subclassed, allowing the compiler to emit direct function pointer calls (devirtualization) rather than dynamic vtable lookups.

### Dependency Topological Ordering
The initialization sequence follows a strict dependency graph:
1. `initialSessionVM`: Synchronously queries `UserDefaults` and Keychain for an existing session.
2. `sessionHolder`: Instantiated with the initial session snapshot.
3. `service` (`LocationService`): Instantiated and injected into `_mapViewModel`.
4. `transport` (`PeerTransportService`): Instantiated as the master radio engine.
5. `relayPolicyManager`: Injected with `transport` so it can throttle stranger forwarding.
6. `routing` (`RoutingTable`): Instantiated to store AODV routing state.
7. `routeDiscoveryService`: Wires `routing`, `transport.neighborTable`, `transport`, and `cryptoService`.
8. `chatEngine`: Wires `transport`, `cryptoService`, `routingTable`, `neighborTable`, and `rateLimiter`.
9. `Dangling Live Activity Cleanup`: If the user force-killed the app or the device rebooted without an active session, a background `@MainActor Task` immediately dismisses orphaned Lock Screen widgets.

## 2.6 The Two-Tier Stale Peer Recovery Supervisor

```swift
            // 6. Stale Peer Accelerated Cadence & Two-Tier AODV Probe Supervisor
            group.addTask { @MainActor in
                var lastGlobalRouteReqDispatch: Date = .distantPast
                var lastRouteReqTimes: [String: Date] = [:]
                while !Task.isCancelled {
                    try? await Task.sleep(nanoseconds: 1_000_000_000)
                    guard !Task.isCancelled else { break }
                    
                    let now = Date()
                    let timing = MeshTimingConfiguration.default
                    
                    // Stage 1 Check: Accelerate cadence while any peer is stale within recovery window (30s < age <= 90s)
                    let anyStale = sessionViewModel.members.contains {
                        $0.isWithinStaleRecoveryWindow(
                            now: now,
                            staleThreshold: timing.stalePeerThreshold,
                            recoveryTimeout: timing.staleRecoveryTimeout
                        )
                    }
                    if anyStale != locationService.hasStalePeers {
                        locationService.hasStalePeers = anyStale
                        if anyStale {
                            locationService.triggerCadenceEvaluation()
                        }
                    }
                    
                    // Stage 2 Check: On-demand AODV ROUTE_REQ staggered across multiple stale peers
                    if now.timeIntervalSince(lastGlobalRouteReqDispatch) >= timing.staleRouteReqStaggerInterval {
                        let eligibleMembers = sessionViewModel.members.filter {
                            $0.isEligibleForStaleRouteDiscovery(
                                now: now,
                                staleThreshold: timing.stalePeerThreshold,
                                routeReqDelay: timing.staleRouteReqDelay,
                                recoveryTimeout: timing.staleRecoveryTimeout
                            ) && now.timeIntervalSince(lastRouteReqTimes[$0.id] ?? .distantPast) >= 10.0
                        }.sorted { $0.lastSeen < $1.lastSeen }
                        
                        if let target = eligibleMembers.first {
                            lastGlobalRouteReqDispatch = now
                            lastRouteReqTimes[target.id] = now
                            Task {
                                _ = try? await routeDiscoveryService.initiateDiscovery(
                                    to: target.id,
                                    session: session,
                                    timeout: 3.0
                                )
                            }
                        }
                    }
                }
            }
```

### Two-Tier Recovery Mathematics
* **Problem**: Festival environments suffer from transient radio occlusions (e.g., walking behind a speaker tower). Firing immediate network-wide AODV flood queries on every dropped ping causes broadcast storms.
* **Tier 1 (30s < age $\le$ 90s)**: Local acceleration. If any member has not been heard from in 30 seconds, `locationService` accelerates its own publishing interval to 2 seconds in case the lost friend is within direct hearing range.
* **Tier 2 (45s < age $\le$ 90s)**: On-demand multi-hop discovery. If the friend remains missing after 45 seconds, TeeKum initiates an AODV `ROUTE_REQ` across the communal mesh.
* **Global Staggering**: `staleRouteReqStaggerInterval` ensures that if multiple friends are lost simultaneously, route requests are staggered one-by-one sorted by oldest `lastSeen`, preventing radio contention.

# 3. `AppRootView.swift`: View Transitions & Lifecycle

```swift
/// Plain root view that presents either GroupPairingView or MainMapView based on session state.
struct AppRootView: View {
    @Bindable var sessionViewModel: GroupSessionViewModel
    var mapViewModel: MapViewModel
    var sosViewModel: SOSViewModel
    var meetingPointViewModel: MeetingPointViewModel
    var chatViewModel: ChatViewModel
    var relayPolicyManager: RelayPolicyManager
    var peerTransport: PeerTransportService
    
    var onSessionStart: (GroupSession) async -> Void
    var onSessionEnd: () async -> Void
    
    var body: some View {
        Group {
            if sessionViewModel.hasActiveSession, let session = sessionViewModel.activeSession {
                MainMapView(...)
                .task(id: session.sessionId) {
                    await onSessionStart(session)
                }
            } else {
                GroupPairingView(...)
                .task {
                    await onSessionEnd()
                }
            }
        }
    }
}
```

### Lifecycle Analysis
* `.task(id: session.sessionId)`: Uses SwiftUI's identity-keyed task modifier. If the user transitions from Session `0x7E3A` to Session `0x4321`, SwiftUI automatically:
  1. Cancels the existing asynchronous task.
  2. Executes `onSessionEnd()` cleanup.
  3. Launches a new `onSessionStart()` task for the new session ID.

# 4. `Formatters.swift`: Mathematical & Quantization Foundations

## 4.1 Fixed-Point Coordinate Quantization

```swift
extension CLLocationCoordinate2D {
    public var rawLatitude: Int32 {
        Int32((latitude * LocationPin.coordinateScalingFactor).rounded())
    }
    
    public var rawLongitude: Int32 {
        Int32((longitude * LocationPin.coordinateScalingFactor).rounded())
    }
    
    public static func dequantize(latitudeRaw: Int32, longitudeRaw: Int32) -> CLLocationCoordinate2D {
        LocationPin.dequantize(latitudeRaw: latitudeRaw, longitudeRaw: longitudeRaw)
    }
}
```

### Derivation of the $\sim$11mm Scaling Bound
* Standard `Double` precision latitude/longitude consumes **8 bytes** each (16 bytes total).
* By multiplying by `coordinateScalingFactor = 10,000,000` ($10^7$), coordinates are mapped into a signed 32-bit integer (`Int32`, **4 bytes** each, 8 bytes total):
  $$\text{Max Earth Latitude} = +90.0^\circ \implies 90.0 \times 10^7 = +900,000,000 < 2,147,483,647 \, (2^{31} - 1)$$
* One degree of latitude along a meridian is $\approx 111,320$ meters:
  $$\text{Resolution} = \frac{111,320 \text{ m}}{10^7} \approx 0.0111 \text{ meters} \approx 11.1 \text{ millimeters}$$
* Result: **Saves 8 bytes per packet** while preserving centimeter-level GPS precision.

## 4.2 Compass Heading 1-Byte Quantization

```swift
extension CLLocationDirection {
    public var quantizedHeadingByte: UInt8 {
        UInt8(min(255, max(0, Int((self * 255.0 / 360.0).rounded()))))
    }
    
    public static func fromHeadingByte(_ byte: UInt8) -> CLLocationDirection {
        Double(byte) * 360.0 / 255.0
    }
}
```

### Mathematical Quantization Bound
* `CLLocationDirection` is natively an 8-byte `Double` ($0.0^\circ \dots 359.9^\circ$).
* Mapping $0.0^\circ \dots 360.0^\circ$ into $0 \dots 255$ (`UInt8`):
  $$\text{Angular Step} = \frac{360.0^\circ}{255} \approx 1.411^\circ$$
* Human compass headings and vision cone wedges have an angular width of $52^\circ$. A $1.4^\circ$ quantization step is imperceptible to the human eye while **saving 7 bytes** on the wire.

## 4.3 Tactical Clock Direction Trigonometry

```swift
extension Double {
    public var clockDirection: String {
        let normalized = (self + 360.0).truncatingRemainder(dividingBy: 360.0)
        let hour = Int((normalized + 15.0) / 30.0) % 12
        let displayHour = hour == 0 ? 12 : hour
        if displayHour == 12 {
            return "Ahead"
        } else if displayHour == 6 {
            return "Behind"
        } else {
            return "\(displayHour) o'clock"
        }
    }
}
```

### Centered Bin Math
* Each clock face hour occupies $\frac{360^\circ}{12} = 30^\circ$.
* Adding $+15.0^\circ$ before dividing by $30^\circ$ centers the bin around each clock number:
  * Ahead (12 o'clock): $345.0^\circ \dots 15.0^\circ$
  * 1 o'clock: $15.0^\circ \dots 45.0^\circ$
  * 2 o'clock: $45.0^\circ \dots 75.0^\circ$
  * Behind (6 o'clock): $165.0^\circ \dots 195.0^\circ$

## 4.4 Zero-Allocation Static Date Formatters

```swift
extension Date {
    private static let shortTimeFormatter: DateFormatter = {
        let f = DateFormatter()
        f.dateFormat = "HH:mm"
        return f
    }()
    
    public var formattedShortTime: String {
        Self.shortTimeFormatter.string(from: self)
```

### Performance & Memory Rationale
* Initializing a `DateFormatter` requires querying ICU locale databases, allocating timezone structures, and parsing date patterns—consuming several milliseconds of CPU time.
* Allocating formatters inside SwiftUI `body` evaluations causes UI stuttering and rapid memory churn.
* Storing formatters as static singletons guarantees **zero heap reallocations** during 60 FPS list scrolling.

# 6. Failure Modes & Edge-Case Recovery Matrix

| Scenario / Failure Mode | Root Cause | Code Handling | Recovery Outcome |
| :--- | :--- | :--- | :--- |
| **App crash or force-kill while session active** | OS terminates process without executing clean shutdown | `TeeKumApp.init()` checks `!hasActiveSession` and dispatches `LiveActivityManager.shared.cleanupDanglingActivities()` | Orphaned Lock Screen widgets are immediately purged upon relaunch |
| **Battery drops below 20%** | Device enters Low Power Mode | `TeeKumApp.body` detects `isSurvivalModeActive` and terminates stranger relay and Live Activities | Phone battery is conserved exclusively for emergency SOS |
| **Simultaneous outbound dialing** | Two devices discover each other simultaneously on Bonjour | `PeerTransportService.shouldAcceptInbound` compares lexicographical peer IDs | Lower ID node yields to higher ID node; exactly 1 connection formed |
| **Friend moves behind a concrete stage wall** | Direct AWDL Wi-Fi link drops | Two-Tier supervisor detects `isWithinStaleRecoveryWindow` and dispatches staged AODV `ROUTE_REQ` | Route is re-established via intermediate festival attendees |
| **Corrupted byte stream over radio** | Packet boundary lost due to radio interference | `StreamMessageFramer.processIncomingChunk` slides forward 1 byte at a time seeking magic header | Resynchronizes without dropping the socket connection |
